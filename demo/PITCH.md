Until real outputs and their provenance are confirmed, open with:
“This is a synthetic development demonstration. The interface works; these
numbers do not establish a model advantage.” For unverified files use
“unverified development data” instead. Do not remove that qualification merely
because `_fake` is absent.

| Time | Screen / action | Talking point |
|---|---|---|
| 0:00–0:20 | Problem and Compare | Cache memory is limited. Can hourly forecasts choose useful articles before demand arrives? |
| 0:20–0:50 | Supplied summary | Explain cached views / all views. Identify the cache size and horizon. The oracle uses hindsight and is only a ceiling. Quote measured numbers only after validation. |
| 0:50–1:25 | Replay, then pause | Show a couple of hours. Point out article views and explicit cache decisions. The leaderboard is a top-50 sample; the hit-rate denominator is all supplied views. |
| 1:25–2:10 | Catch a surge | Choose a team-validated event. Explain onset, trajectory and catch lanes. 0h means at arrival; 24h is capped. Do not claim advance prediction from a lag of 0. |
| 2:10–2:40 | Look ahead | Show supplied 1/2/3/6-hour results. State what the actual curve shows, including a tie or loss. Do not promise monotonic improvement or superiority. |
| 2:40–3:00 | Limits | Hourly decisions, equal page sizes and unpredictable first-hour shocks. End with the team's measured conclusion, or state that evaluation is pending. |

Use Reset walkthrough before starting. It stops playback and resets the main
replay; select your rehearsed event separately. Story navigation pauses replay.

JSON delivery path. Keep a local copy of the verified output for judging.
